# 복합 질문 분해 검색 A/B 실험

기준일: 2026-10-12 (한국 시간). 기존 `ask_selected` 기본 경로는 유지한다.
이 문서는 `decomposition_v1` 실험 기록이며, 과거 최종 벤치마크를 대체하지 않는다.

## 목적과 방법

질문을 항목별로 나누면 동일한 최종 근거 예산에서 필요한 근거를 더 확보하는지 확인한다.

- A: 원래 질문으로 현재 `vector_context` 검색을 실행한다.
- B: Gemini에 **원래 질문만** 전달하여 최대 4개 하위 질문을 만든다. 각 하위 질문과 원래 질문으로 같은 검색기를 실행한다.
- B의 최종 근거는 원래 검색 1위 하나를 먼저 보존한 뒤, 하위 질문별 결과와 원래 결과를 번갈아 선택한다. 동일 원문 구간 및 동일 공지 범위의 동일 본문을 중복 제거한다.
- 두 방식 모두 최대 5묶음, 묶음당 512, 제목·본문 합계 2,200 E5 토큰을 사용한다. 총량은 상한을 같게 한 것이며 실제 사용 토큰을 강제로 같게 채우지는 않는다.
- 생성 모델·시스템 프롬프트·원래 질문·출력 상한은 같다. 하위 질문 자체나 정답표를 답변 생성 입력에 넣지 않는다.
- 한 항목만 반환하거나 잘못된 형식·새 숫자가 있는 분해는 원래 질문으로 돌아간다. 이 검사는 연도·대상 조건의 의미 보존까지 보장하지 않는다.
- 검색 결과를 번갈아 선택하는 것은 **각 항목을 실제로 뒷받침하는지 검사하는 절차가 아니다**. 이번 실험은 추가 근거 확인·재검색 전 단계다.

[Decomposed Prompting](https://arxiv.org/abs/2210.02406)과
[LlamaIndex SubQuestionQueryEngine](https://developers.llamaindex.ai/python/examples/query_engine/sub_question_query_engine/)의
질문 분해 방식을 참고했다. 해당 구현 전체를 도입하거나 논문의 점수를 재현한 것은 아니다.
[IRCoT](https://aclanthology.org/2023.acl-long.557/)처럼 중간 결과에 따라 반복 검색하는 단계는 포함하지 않았다.

## 사전 고정 평가

- 개발: 기존 최종 벤치마크 32문항(답변 가능 24, 행동 8). 이미 분석한 문항이므로 독립 검증으로 부르지 않는다.
- 새 검증: 12문항(복합 8, 단순 2, 행동 2). 정답 공지 10개는 기존 `eval/` 평가 기록의 공지 ID와 겹치지 않는다. 유사 주제와 원문 자체는 코퍼스에 남아 있다.
- 원문에서 정답을 확인하고 질문·항목별 근거 문구·판정 기준을 검색 실행 전에 고정했다. 새 검증 문항의 정답 출처는 모두 HTML 공지다.
- 항목별 검색 점수는 **반환된 본문 여러 개의 합집합**에서 같은 공지 범위의 필수 문구를 확인한다. 이전의 단일 근거 묶음 Hit@5와는 정의가 다르다.
- 문구 검사는 동의어·대체 출처를 놓칠 수 있다. 자동 점수는 수정하지 않고, 답변 완전성·주장과 인용의 관계는 별도 assistant 검토로 남긴다.
- 사람 승인 평가가 아니며 단일 생성 표본이다. 동일한 근거에서 나온 답변 차이를 검색 개선 효과로 단정하지 않는다.
- 결과를 본 뒤 검색·분해 프롬프트·라벨을 조정하지 않는다. 새 실험에서 튜닝하려면 새 검증 세트가 필요하다.

사전 기준은 [프로토콜](../eval/decomposition_protocol_v1.json), 질문은
[개발 세트](../eval/decomposition_development_v1.jsonl)와
[새 검증 세트](../eval/decomposition_holdout_v1.jsonl)에 있다.

## 실행과 복구

```bash
.venv/bin/python scripts/run_decomposition_throttled.py \
  --cases eval/decomposition_development_v1.jsonl \
  --output-dir data/processed/decomposition-dev-new --live

.venv/bin/python scripts/run_decomposition_throttled.py \
  --cases eval/decomposition_holdout_v1.jsonl \
  --output-dir data/processed/decomposition-holdout-new --live
```

로컬 E5 모델·원문·선별 인덱스와 기존 Gemini 키가 필요하다. 출력 폴더는 새 경로여야 한다.
실제 API 사용량이 발생한다. 문항당 분해 1회와 방식별 답변 최대 2회, 총 최대 5회로 제한한다.
호출 간 최소 6초를 둔다. 이 대기는 답변 제공 속도 자체와 별도로 해석해야 한다.

공급자 오류로 중단되면 다음과 같이 이미 생성한 답변과 계획을 보존하여 이어간다.

```bash
.venv/bin/python scripts/resume_decomposition.py \
  --report data/processed/decomposition-dev-new/report.json \
  --frozen data/processed/decomposition-dev-new/frozen.json \
  --cases eval/decomposition_development_v1.jsonl \
  --output-dir data/processed/decomposition-dev-resume-new
```

재시도도 원래 방식별 2회 한도에 포함된다. 이를 다 쓴 문항을 성공할 때까지 반복하지 않는다.
분해 API 실패는 원래 질문 검색으로 대체하고 그 사실을 기록한다. 완료 답변은 다시 생성하지 않는다.
복구 도구는 평가 운영용이며 동결된 검색·생성 코드는 바꾸지 않는다.
SDK가 반환하지 않은 오류 호출의 토큰은 알 수 없으므로 관측 합계를 청구 총량으로 단정하지 않는다.

## 결과와 판정

**현재 기본 경로로 승격하지 않고 실험용으로 유지한다.** 새 검증에서 일부 근거·인용은 개선됐지만,
엄격한 완전 답변 수는 늘지 않았고 개발 문항에서 정답 근거를 잃는 회귀가 있었다.

| 지표 | A: 현재 검색 | B: 분해 검색 |
|---|---:|---:|
| 개발: 항목별 근거 문구 확보 | 51/58 | 50/58 |
| 개발: 모든 항목 근거 확보 | 19/24 | 19/24 |
| 개발: 양쪽 생성 완료 문항의 완전 정답 | 17/23 | 16/23 |
| 개발: 전체 답변 가능 문항의 완전 정답 | 18/24 | 16/24 |
| 개발: 행동 기준 충족(상태 코드 포함) | 8/8 | 7/8 |
| 새 검증: 항목별 근거 문구 확보 | 17/21 | 18/21 |
| 새 검증: 모든 항목 근거 확보 | 7/10 | 8/10 |
| 새 검증: 사전 rubric의 모든 조건을 포함한 정답 | 9/10 | 9/10 |
| 새 검증: 위 정답 중 실제 인용도 뒷받침하는 답변 | 7/10 | 8/10 |
| 새 검증: 단순 질문 정답 | 2/2 | 2/2 |
| 새 검증: 행동 기준 충족 | 2/2 | 2/2 |

검색 점수는 문구·공지 범위 기반 자동 프록시, 답변 점수는 assistant의 의미 검토다.
사람 승인 결과나 전체 서비스 정확도 추정치로 사용하지 않는다.
개발 B17의 B 답변은 API 오류로 2회 한도를 소진하여 미수신했다. 따라서 전체 24문항 비율과
양쪽 응답이 모두 있는 23문항 비율을 함께 표시했다. B30의 B는 실제 거절 내용은 적절하지만
`insufficient_evidence` 대신 `needs_clarification`을 반환했다. 이를 개인정보 유출로 해석하지 않는다.

### 개선·회귀와 측정 한계

- **B01 환불:** B가 실제 환불 구간을 새로 확보하여 2/3 환불과 1월 3일 0시 이후 불가를 모두 답했다.
- **B03 생리공결:** A의 3위 정답 근거가 B의 최종 5개에서 빠졌다. 원래 1위만 보존하고 하위 질문의 후보를 번갈아 넣는 규칙은 기존의 유용한 2~5위 근거를 보호하지 못한다.
- **B05 대학영어:** 2025년 질문에 B가 2026년 근거를 인용했다. 질문에 연도를 남기는 프롬프트만으로는 검색 결과의 적용 시점까지 보장하지 못한다.
- **D04 성인지교육:** B가 빠져 있던 2026년 무료 참가비를 찾았다. 장소·양일 참석·무료라는 핵심 사실은 맞다. 다만 실행 전에 정한 rubric의 **교육시간 준수** 조건까지 명시하지 않아, 엄격한 완전 답변에서는 A와 B 모두 실패로 유지했다. 근거 확보 개선과 완전 답변 개선을 구분한다.
- **D07 분납:** 두 답변의 메뉴·전액고지서 안내 내용은 정답 원문과 같다. A는 메뉴를 담지 않은 근거를 인용했고, B는 같은 학기의 다른 공식 공지에서 메뉴와 고지서 제한을 확보하여 올바르게 인용했다. 지정 정답 공지 ID와 달라 자동 검색 점수는 양쪽 모두 0/2로 보존했다. 점수를 사후 수정하지 않았다.
- **D08 군 e-러닝:** 두 답변의 사실은 정답 원문과 같지만, 훈련 관련 예외 불가를 다른 학기의 근거로 인용했다. 답변 내용의 정확성과 인용의 적용 범위를 별도로 평가했다.
- B02·B08·B10·B20·B21, D03·D08 등에서 일부 하위 질문이 공통 연도·학기·제도 조건을 생략했다. B20은 장학금 종류까지 빠졌다. 구조 검증만으로는 이런 의미 손실을 잡지 못했다.
- B17은 `1:1`을 `11`로 바꾼 분해를 거부했다. D05는 로마숫자 `Ⅰ`을 숫자 `1`로 바꾼 유효한 표현도 거부하여 원래 질문으로 돌아갔다. 숫자 검사는 과잉 거부 가능성이 있다.
- B12·B18은 분해 API 실패로 원래 질문 검색을 사용했다. B12의 이메일 부재 단정, B18의 현장/온라인 선택 가능 오해 등 **동일 입력에서 발생한 생성 차이를 분해 검색의 효과로 돌리지 않는다.**
- 이번 방식에는 항목별 근거의 의미적 충분성 검사·조건에 맞는 재정렬·부족분만 추가 검색하는 단계가 없다.

### 사용량과 운영

개발은 103회 호출 중 94회 응답, 새 검증은 36회 모두 응답했다.
전체 관측 사용량은 263,604토큰이며 실패 9회의 미확인 사용량은 제외됐다.
개발 초반 429 오류 때문에 호출 간격을 6초로 늘렸다. 완료한 답변은 다시 생성하지 않았다.
검색·분해·생성 프롬프트 및 정답은 실행 중 변경하지 않았으며 최종 동결 지문 검사가 통과했다.

오류가 없는 새 검증에서 A는 총 32,930토큰, B 답변은 34,249토큰,
B의 분해는 3,755토큰이었다. **B 총량은 38,004토큰으로 A보다 약 15.4% 많았다.**
이는 입력+출력 토큰 비교이며 금액 기준 청구 비용은 아니다.
호출 간 대기를 제외한 응답 시간 중앙값은 A 생성 1.465초, B 생성 1.518초,
분해 1.132초였다. 서로 다른 단계의 중앙값을 합쳐 실제 종단 지연으로 부르지 않는다.
검색 시간에는 A/B 질의의 일괄 임베딩이 함께 포함돼 독립적인 A 응답시간으로 사용할 수 없다.

전체 코드 테스트 **467개 통과**. 이는 답변 정확도 검증 개수와 다르다.

## 후속 실험의 우선순위

1. 연도·학기·제도·대상 조건을 구조화하여 하위 질문마다 보존하고, 후보 문서의 적용 범위를 검사한다.
2. 후보를 번갈아 채우기 전에 항목별로 직접 답을 담고 있는지 판단한다. 원래 검색의 유효한 근거도 함께 비교한다.
3. 부족한 항목만 해당 공지 본문·첨부에서 추가 검색하고, 필수 조건·예외까지 포함했는지 답변 단계에서 확인한다.

이 세트의 결과를 보고 위 방법을 튜닝하면 본 새 검증 세트도 개발 자료가 된다. 다음 성능 주장은
새로 고정한 질문에서 검증해야 한다. 이번 작업에서는 이 후속 변경을 적용하지 않았다.
