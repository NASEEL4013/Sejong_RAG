# 구형 DOC 변환 및 PDF OCR 복구

## 본문 이미지 처리 추가 (2026-10-07)

공지 웹페이지 안의 이미지도 수집 대상으로 처리한다. 첨부 PDF용 OCR과 별도 경로이며, 저장된 원본 HTML을 다시 읽어 과거 공지에도 적용할 수 있다. 텍스트 본문이 있는 공지의 이미지도 포함한다.

```bash
# 요청 없이 대상 개수만 확인
.venv/bin/python -m sejong_rag.notice_images --dry-run
# 공식 본문 이미지를 최소 10초 간격으로 수집하고 로컬 글자 인식
.venv/bin/python -m sejong_rag.notice_images
# 같은 주소의 이미지가 교체됐는지도 확인
.venv/bin/python -m sejong_rag.notice_images --refresh
```

원본 이미지는 `data/raw/notice-images/`, 추출 결과와 실패 사유는 `data/processed/notice-images/`에 저장한다. 결과에는 공지 연결, 이미지 주소·순서, 내용 해시(파일 내용의 지문), 인식 신뢰도를 보존한다. 공식 HTTPS 호스트만 허용하고 다른 주소로의 자동 이동을 막으며 파일 크기를 제한한다. 기존 파일은 기본적으로 재사용한다. 새 공지 본문을 수집한 뒤 이 명령을 실행하고, 이미지 교체 확인에는 `--refresh`를 사용한다.

이미지 인식 결과는 신뢰도가 높아도 자동 검증 완료로 취급하지 않는다. 통합 청킹(검색용 문서 조각 생성) 시 검토용 자료로만 들어가며 `--include-review` 검색으로 확인할 수 있다. 기본 검색에 쓰이는 공지 본문에는 이미지 미검증 경고를 넣어 이미지의 조건을 놓친 채 확정 답변하지 않도록 한다. 실패한 이미지도 보고서에 남고 재실행 시 글자 인식을 다시 시도한다.

자료 반영 순서는 `notice_images` → `unified_chunk` → 신뢰·검토 인덱스의 `embed_chunks` 재생성이다. 예시는 [통합 인덱스](UNIFIED_INDEX.md)의 생성 명령을 따른다. 인덱스는 검색을 위한 저장 구조다. 이미지 처리만 실행하고 인덱스를 갱신하지 않으면 검색 결과에는 반영되지 않는다.

현재는 본문 `<img>`의 `data-src` 또는 `src` 주소를 처리한다. 배경 이미지, 외부 호스트, 별도 실행이 필요한 웹 콘텐츠는 자동 수집하지 않는다. OCR 결과의 날짜·숫자·조건은 원본 대조 전 단독 확정 근거로 사용하지 않는다.

이번 기존 자료 보완 결과: 공지 28건의 본문 이미지 58개를 수집했고 모두 글을 추출했다. 이 중 첫 시도에서 실패한 작은 화면 캡처 등 6개는 흩어진 글자를 읽는 추가 인식 방식으로 복구했다. 전체를 원본 대조한 것은 아니므로 58개 모두 검토 대상으로 유지한다. 검색용 조각 98개를 추가해 신뢰 10,663개·검토 3,489개, 합계 14,152개가 됐다. 출처 누락과 분할 길이 제한 초과는 없었다.

> 현재 기준 안내(2026-08-10): 파이프라인 완성 후 전체 자동 테스트는 148개 통과했다. 본문에 더 작은 테스트 수가 있으면 해당 기능을 만들던 당시의 기록이다. 최신 전체 성능은 [독립 평가 보고서](HOLDOUT_EVALUATION.md)를 참고한다.


## 목적

기본 첨부 추출에서 읽지 못한 구형 DOC와 이미지 기반 PDF 페이지를 로컬 도구로 보완한다. 학교 문서를 외부 AI API에 전송하지 않으며 원본 파일은 수정하지 않는다.

## 처리 방법

실행 명령:

    .venv/bin/sejong-recover-attachments

- DOC: LibreOffice 7.3 headless로 임시 DOCX 변환 후 문단·표 추출
- PDF: 내장 텍스트가 없는 페이지만 Poppler로 300DPI PNG 렌더링
- OCR: Tesseract 한국어+영어 모델 사용
- 추적 정보: 페이지, OCR 여부, 평균 단어 신뢰도, 도구와 원본 보존 여부 기록
- 재실행: 완료한 문서는 건너뛰고 남은 페이지만 처리

## 실제 결과

- 구형 DOC: 5/5개 변환 및 텍스트 추출 성공
- OCR 대상 PDF: 6개
- OCR 대상 페이지: 57페이지
- OCR 성공: 57페이지
- OCR 실패: 0페이지
- 텍스트가 없는 PDF 페이지: 0페이지
- OCR 평균 신뢰도: 71.3
- OCR 신뢰도 중앙값: 73.5
- 최소/최대 신뢰도: 32.6 / 90.3
- 신뢰도 60 미만: 7페이지
- 전체 첨부 보고서: 성공 135개, 검토 필요 11개, 실패 0개
- 전체 텍스트 record: 50,808개
- 전체 추출 문자: 10,180,810자
- 전체 자동 테스트: 87개 통과

## 정확도 해석

Tesseract 신뢰도 71.3은 문서 정확도가 71.3%라는 뜻이 아니다. OCR 엔진이 인식한 단어별 확신도를 평균한 보조 지표다. 높은 신뢰도에서도 `0/O`, `1/l`, 날짜 구분점, 학점과 금액이 틀릴 수 있다.

따라서 OCR을 사용한 PDF 6개는 텍스트 검색 후보로는 보존하지만 자동으로 신뢰 가능한 근거로 승격하지 않는다. 특히 날짜, 금액, 학점, 신청 조건을 답할 때는 원본 페이지 대조 또는 별도의 OCR 평가를 통과해야 한다.

구형 DOC 5개는 변환 후 구조화된 문단·표 텍스트가 생성됐고 오류 없이 처리됐으므로 `success`로 변경했다. 다만 LibreOffice 변환 과정에서 복잡한 배치가 달라질 수 있으므로 표 관계가 중요한 답은 원본 대조 원칙을 유지한다.

## 남은 검토 문서

검토 필요 11개는 다음과 같다.

- OCR을 사용한 PDF 6개
- 내부에 EXE만 있는 ZIP 2개
- 내부 구형 XLS 또는 일부 미지원 파일이 남은 ZIP 3개

다음 단계에서는 OCR 6개에서 질문에 직접 사용될 핵심 숫자·날짜 표본을 원본과 대조해 OCR 활용 기준을 정한 뒤, 성공 문서 중심의 다문서 청킹과 인덱스를 구축한다.

## 후속 원본 대조

OCR 신뢰도 60 미만 7페이지를 원본 이미지와 직접 대조하고 검색 텍스트를 교정했다. 세부 결과와 확정 활용 기준은 `docs/OCR_VALIDATION.md`에 기록했다. 검증하지 않은 OCR 50페이지는 확정 답변의 단독 근거로 사용하지 않는다.
