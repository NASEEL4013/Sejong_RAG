# 첨부파일 텍스트 추출 결과
> 현재 기준 안내(2026-08-10): 파이프라인 완성 후 전체 자동 테스트는 148개 통과했다. 본문에 더 작은 테스트 수가 있으면 해당 기능을 만들던 당시의 기록이다. 최신 전체 성능은 [독립 평가 보고서](HOLDOUT_EVALUATION.md)를 참고한다.


## 왜 이 단계가 필요한가

임베딩 모델은 PDF, HWP, XLSX 파일 자체가 아니라 파일에서 꺼낸 텍스트를 입력받는다. 따라서 파일 형식별로 텍스트를 추출하고 원본 위치를 보존해야 검색 결과에 페이지·시트·슬라이드 등의 출처를 붙일 수 있다.

## 구현

실행 명령:

    .venv/bin/sejong-extract-attachments

출력:

- `data/processed/attachments/records/{attachment_id}.jsonl`: 검색·청킹 전 단계의 텍스트 단위
- `data/processed/attachments/reports/{attachment_id}.json`: 파일별 성공 여부, 경고, 텍스트 길이

형식별 위치 정보:

- PDF: 페이지
- XLSX: 시트와 행
- DOCX: 문단 또는 표와 행
- PPTX: 슬라이드
- HWP: 문서 단위
- ZIP: 내부 파일 경로와 내부 문서 위치

ZIP은 경로 탈출, 파일 개수, 개별 크기, 총 압축 해제 크기, 중첩 깊이를 제한한다. EXE는 절대 실행하지 않는다.

## 남은 정확도 공백

- 구형 DOC 5개: LibreOffice로 DOCX 변환 후 모두 추출했다.
- 이미지 기반 PDF: 6개 PDF의 빈 텍스트 57페이지를 한국어·영어 OCR로 보완했으며 원본 대조 전까지 검토 필요다.
- ZIP 3개: 내부 XLS 등 일부 구형 형식을 아직 읽지 못한다.
- ZIP 2개: 내부 내용이 EXE뿐이다. 보안을 위해 실행·추출하지 않았다.
- PDF 파서 경고: 회전 글자와 일부 고급 한글 인코딩은 불완전할 수 있다.
- XLSX: 수식은 수식 문자열을 보존하지만 계산 결과와 화면 배치를 완전히 재현하지 않는다.
- HWP: 텍스트는 추출하지만 현재 위치 정보가 페이지가 아니라 문서 단위다.

따라서 `success` 문서만 먼저 인덱싱할 수 있으며, `review_required`와 `failed` 문서는 OCR·변환 보완 전까지 정확한 답변 근거에서 제외하거나 경고를 동반해야 한다.
