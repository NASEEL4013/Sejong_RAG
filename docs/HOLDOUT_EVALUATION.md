# 통합 홀드아웃 검색·생성·안전 행동 평가

## 목적

기존 21문항은 검색 규칙을 조정할 때 사용했으므로 실제 일반화 성능을 과대평가할 수 있다. 개발에 사용하지 않은 32개 정답형 질문과 4개 안전 행동 질문을 별도로 만들고 검색과 Gemini 생성을 분리 평가했다.

홀드아웃(holdout)은 개발 중 정답을 보지 않는 최종 시험 문제를 뜻한다. 이번 32문항은 최초 평가 후 실패 분석과 개선에 사용했으므로, 앞으로는 미공개 홀드아웃이 아니라 회귀 평가셋으로 사용한다. 회귀 평가는 새 변경이 기존 기능을 다시 고장 내지 않는지 확인하는 시험이다.

## 평가 데이터

- `eval/holdout_questions.jsonl`: 정답형 32문항
- `eval/holdout_generation_expectations.jsonl`: 자연어 답변 핵심 개념과 허용 표현
- `eval/holdout_behavior_questions.jsonl`: 모호함·개인정보·미래 일정·조건 부족 4문항
- 분야: 수강 9, 학적 6, 학점교류 1, 졸업 6, 등록금 2, 장학 8

## 검색 결과

최초 하이브리드 검색:

- Hit Rate@5: 0.84375
- MRR: 0.73217

개선 후:

- Hit Rate@5: 1.0
- MRR: 0.86458
- 기존 튜닝 21문항: Hit Rate@5 1.0, MRR 0.79365 유지

Hit Rate@5는 정답 청크가 상위 5개 안에 포함된 비율이다. MRR(Mean Reciprocal Rank, 평균 역순위)은 첫 정답이 얼마나 앞에 배치되는지를 측정한다.

주요 개선은 졸업학점·전공필수 표현의 졸업표 의도 인식, 입학년도 구간과 학과 행 결합, 개인 졸업심사 명단 감점, 학위증과 학위수여식 연결, 계절학기 기간 의도 보정이다.

## Gemini 생성 결과

최초 32문항 실행에서는 평가기 오탐과 답변 누락을 발견했다. 복합 인용 `[근거 1, 근거 2]` 파싱, 질문 범위 판정, 자연어 동치 표현을 수정하고 실제 누락 문항만 재평가했다.

최종 결과:

- 핵심 답변값 정확도: 1.0
- 정답 출처 문맥 포함률: 1.0
- 정답 공식 출처 인용률: 1.0
- 인용 번호 유효율: 1.0
- 모든 자동 검사 동시 통과: 1.0 (32/32)
- 결과: `data/evaluation/holdout-gemini-final.jsonl`

## 안전 행동 결과

- 장학사업명 없는 질문: 사업명과 학기를 요청
- 개인 졸업 가능 여부: 학번·성명을 요청하지 않고 학사정보시스템 자가진단 안내
- 수집되지 않은 2027-2 일정: 날짜를 추측하지 않음
- 학과 없는 졸업학점 질문: 학과와 단일·복수전공 여부 요청
- 결과: 4/4 통과
- 결과 파일: `data/evaluation/holdout-behavior.jsonl`

## 재실행

```bash
.venv/bin/sejong-evaluate-unified --eval eval/holdout_questions.jsonl --top-k 5 --candidate-k 300
.venv/bin/python -m sejong_rag.evaluate_unified_generation --resume --delay 1.5
.venv/bin/python -m sejong_rag.regrade_holdout
.venv/bin/python -m sejong_rag.evaluate_behavior
.venv/bin/pytest -q
```

## 남은 한계

- 32문항은 실패 수정에 사용됐으므로 새 검색 알고리즘을 크게 바꿀 때는 새로운 미공개 질문을 추가해야 한다.
- 학과별 단일전공 학점 숫자는 2019~2026의 402행을 검증했지만, 과목명 단위 좌표 대조는 2021 소프트웨어학과가 첫 검증 사례다.
- 2025년부터 소프트웨어학과는 콘텐츠소프트웨어학과 공식 행으로 연결한다.
- 개인 학적 상태는 학교 공지 RAG가 판정하지 않는다.
- 새 공지가 게시되면 수집·추출·인덱스·평가를 다시 실행해야 한다.
