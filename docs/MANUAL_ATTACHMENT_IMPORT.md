# 수동 첨부파일 import
> 역사적 단계 기록: 이 문서는 개발 당시의 구현과 수치를 보존한다. 현재 상태와 실행 방법은 [프로젝트 README](../README.md) 및 [문서 지도](README.md)를 기준으로 한다.


## 목적

상세 HTML에서 확보한 공식 첨부 메타데이터와 사용자가 직접 다운로드한 파일을 안전하게 연결한다. 파일을 단순히 폴더에 넣는 것과 달리 부모 공지, 공식 URL, 첨부번호, 내용 해시와 페이지를 기록한다.

## 1. 필요한 파일과 링크 확인

    .venv/bin/sejong-import-attachments --list

각 항목의 상태:

- `missing`: 공식 목록에는 있지만 `data/manual-input/`에 없음
- `ready`: 파일명이 일치하고 현재 처리 가능한 PDF
- `unsupported`: 파일은 있지만 아직 지원하지 않는 형식

## 2. 직접 다운로드

공식 공지 페이지를 브라우저로 열고 첨부파일을 직접 저장한다. 브라우저가 제공한 파일명을 변경하지 않는 것이 가장 안전하다.

첫 필수 파일:

- `2026학년도 2학기 등록금 납부 안내.pdf`

정확도 우선 정책에서는 번역본도 다운로드 전까지 중복으로 확정하지 않으므로 공식 첨부를 모두 required로 취급한다.

## 3. 파일 배치

다운로드한 파일을 다음 폴더에 넣는다.

    data/manual-input/

이 폴더는 Git에서 제외되므로 원본 PDF가 저장소에 커밋되지 않는다.

## 4. import

    .venv/bin/sejong-import-attachments

도구는 다음을 수행한다.

1. 공식 파일명과 로컬 파일명을 유니코드·공백 정규화 후 비교
2. PDF 파일 서명 `%PDF-` 확인
3. SHA-256 내용 해시 계산
4. `new`, `updated`, `unchanged` 판정
5. 부모 공지와 첨부번호 연결
6. 원본을 `data/raw/manual-attachments/`에 보존
7. 페이지별 텍스트를 `data/processed/pdf/`에 JSONL로 저장
8. 처리 결과를 `data/metadata/imported-attachments/`에 저장

파일명이 일치하지 않는 파일을 유사도만으로 자동 연결하지 않는다. 잘못된 공지에 행정 문서를 연결하면 RAG가 그럴듯하지만 틀린 답을 만들 수 있기 때문이다.

## 현재 지원 범위

- PDF: 파일 검증, 페이지별 텍스트 추출 지원
- HWP/HWPX, DOCX, XLSX: 아직 미지원
- 이미지형 PDF: 페이지는 인식하지만 OCR이 없으므로 텍스트가 비어 있을 수 있음

## 첫 실제 import 결과

- 파일: `2026학년도 2학기 등록금 납부 안내.pdf`
- 문서 ID: `notice3-891311-attachment-236574`
- 부모 공지: `notice3-891311`
- 페이지: 12
- 빈 텍스트 페이지: 0
- SHA-256: `19b766ba37dbdc2ccfa54eee364964392fd8f12b1ea631d9505d05b125697be1`
- 첫 실행: `new`
- 같은 파일 재실행: `unchanged`

1차 텍스트 검사에서 등록금·납부 핵심어와 목차가 추출됐다. 다음 단계에서는 표와 줄 배치를 더 잘 보존하는 레이아웃 추출 후 토큰 청킹을 적용한다.
