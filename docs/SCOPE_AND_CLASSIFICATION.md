# 프로젝트 범위와 공지 분류 결정

## 범위 결정

프로젝트 제품 범위는 `세종대학교 전체 RAG`다. 학사·장학·수강·졸업과 학과별 공식 정보를 모두 다룰 수 있는 구조를 목표로 한다.

소프트웨어학과는 더 이상 수집 필터가 아니다. 기존 수강편람 실험과 평가 데이터는 학과별 조건을 정확히 처리하는 첫 검증 사례로 유지한다. 이후 같은 구조로 다른 학과를 확장한다.

## 왜 전체 자료를 보존하는가

전교 공통 규정과 학과별 예외는 같은 질문에서 함께 필요할 수 있다. 수집할 때 소프트웨어학과 문자열이 없는 문서를 버리면 공통 장학 기준, 수강 규정, 휴·복학 절차를 잃는다. 따라서 원본 카탈로그는 넓게 보존하고 검색 시 메타데이터로 좁힌다.

```text
전체 공식 자료 보존
  → 분야·학과·학년도·학기 메타데이터 부여
  → 질문 조건에 맞는 필터와 검색
  → 근거를 사용한 답변
```

## 첫 분류 방식

`sejong-classify-notices`는 목록 제목과 게시판으로 복수 카테고리를 붙인다.

- scholarship
- course_registration
- graduation
- credit
- academic_status
- curriculum
- tuition
- certification
- department
- academic_general / campus_general

키워드가 발견된 공지는 `high`, 게시판 기본 라벨만 있는 공지는 `normal` 우선순위가 된다. 이는 상세 내용을 먼저 확인할 순서일 뿐, `normal` 문서를 삭제하거나 RAG에서 영구 제외한다는 뜻이 아니다.

## 실제 첫 결과

학사·장학 첫 페이지의 23개 공지를 모두 보존했다.

- high: 20개
- normal: 3개
- scholarship: 10개
- course_registration: 5개
- academic_status: 2개
- credit: 2개
- graduation: 1개
- tuition: 1개

한 공지는 여러 카테고리에 포함될 수 있으므로 카테고리 합계는 문서 수보다 클 수 있다.

## 알려진 한계

제목 규칙은 단순하고 설명 가능하지만 문맥을 완전히 이해하지 못한다. 예를 들어 `학부 재학생 등록금`의 `학부`가 학과 관련 단어로 잡혀 `department`가 과잉 부여됐다. 본문을 수집한 뒤 규칙을 개선하거나 별도의 분류 모델과 비교해야 한다.

분류 메타데이터는 검색을 돕는 힌트이며 공식 문서의 실제 적용 대상을 대신하지 않는다.
