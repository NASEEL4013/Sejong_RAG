# 공식 공지 목록 수집기
> 역사적 단계 기록: 이 문서는 개발 당시의 구현과 수치를 보존한다. 현재 상태와 실행 방법은 [프로젝트 README](../README.md) 및 [문서 지도](README.md)를 기준으로 한다.


## 왜 필요한가

기존 `sejong-ingest`는 상세 공지 URL 하나를 사람이 직접 넣어야 한다. 목록 수집기는 학사·장학 게시판을 주기적으로 확인해 상세 공지 후보를 먼저 발견한다. 이 단계에서는 LLM 학습이나 임베딩을 하지 않고, 앞으로 처리할 문서의 카탈로그만 만든다.

## 동작 과정

1. 게시판 목록 URL에 `article.offset`을 붙여 제한된 페이지만 요청한다.
2. 게시판 표 안에서 `mode=view`와 `articleNo`가 있는 링크만 읽는다.
3. 제목, 담당 부서, 등록일, 첨부 여부, 고정 공지 여부를 저장한다.
4. 같은 `articleNo`가 고정 공지로 여러 페이지에 반복되면 하나로 합친다.
5. 직전 카탈로그와 제목·부서·등록일·URL·첨부 여부를 비교한다.

조회수는 자주 바뀌지만 문서 내용 변경을 뜻하지 않으므로 비교하지 않는다. 일부 페이지만 수집했을 수도 있으므로 현재 목록에 보이지 않는 문서를 자동 삭제하지 않는다.

## 실행

기본값은 학사공지와 장학공지 첫 페이지이며 게시판 사이에 10초를 기다린다.

    .venv/bin/sejong-list-notices

게시판이나 페이지 수를 명시할 수도 있다.

    .venv/bin/sejong-list-notices \
      --board academic_notice \
      --pages 3 \
      --delay 10

`--pages`는 실수로 서버 전체를 빠르게 순회하지 않도록 최대 100으로 제한된다. 실제 요청에서 `--delay`를 10초 미만으로 설정하면 실행을 거부한다.

## 생성 데이터

`data/catalog/notice-index.json`에 다음이 기록된다.

- 수집 시각과 게시판별 수집 페이지 수
- 전체 후보 수
- `new`, `updated`, `unchanged` 문서 ID
- 각 공지의 목록 메타데이터

첫 실제 실행에서는 학사공지 13개, 장학공지 10개로 총 23개를 발견했다. 두 번째 동일 실행에서는 23개 모두 `unchanged`였다.

## robots.txt와 첨부파일 정책

2026-08-09 확인한 세종대학교 `robots.txt`에는 전체 크롤러 대상으로 다음 규칙이 있다.

- `Crawl-delay: 10`
- `Disallow: /*mode=download`
- `Disallow: /_attach/`

따라서 목록 수집기는 최소 10초 간격을 강제한다. 첨부파일 자동 다운로드는 확장하지 않는다. 기존에 확보한 공개 수강편람은 보존하되, 새 첨부자료는 사용자가 직접 제공한 파일을 가져오거나 학교가 허용하는 공식 경로·허가를 확인한 뒤 처리한다.

## 한계와 다음 단계

목록의 `updated`는 목록 메타데이터 변경만 뜻한다. 본문 수정이나 같은 파일명의 첨부 내용 교체는 상세 페이지와 파일 해시를 확인해야 알 수 있다. 다음 단계는 제목 키워드와 게시판을 이용해 관련 후보를 선별하고, 허용된 상세 HTML 본문만 수집하는 것이다.
