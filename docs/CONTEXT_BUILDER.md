# RAG Context Builder

## 목적

검색 상위 chunk만 LLM에 전달하지 않고 같은 페이지의 인접 chunk를 함께 모아, 청크 경계 때문에 정답 문장이 누락되는 문제를 줄인다.

## 설정

- 하이브리드 검색 결과: 상위 3개
- 인접 범위: 같은 문서·같은 페이지의 앞뒤 1개 chunk
- 중복 제거: chunk ID 기준
- 최대 chunk: 6개
- 최대 본문 문자: 6,000자
- 각 근거에 페이지, chunk ID, 선택 이유, 공식 출처 URL 포함

문자 제한은 생성 모델을 정하기 전의 임시 기준이다. 생성 모델마다 tokenizer가 다르므로 모델 선택 후 token 기준으로 변경한다.

## CTX-001 평가 결과

15개 검색 평가 질문에 적용했다.

| 지표 | 검색 Top 5 | 인접 chunk 확장 context |
|---|---:|---:|
| 정답 근거 포함 | 14/15 | 15/15 |
| 근거 포함률 | 0.9333 | 1.0000 |

Context 크기:

- 평균 chunk 수: 9.4개
- 평균 본문 문자: 10,069.8자
- 최대 본문 문자: 11,963자

학점교류 자격 질문의 정답 chunk는 검색 6위였지만, 검색된 같은 157쪽 chunk의 이웃으로 context에 포함됐다.

## 실행

```bash
.venv/bin/sejong-context \
  "학점교류를 신청하려면 평균 평점이 얼마나 되어야 해?"
```

## 한계와 다음 실험

- 근거 포함률은 높아졌지만 입력이 평균 약 1만 자로 커졌다.
- 관련 없는 인접 내용이 LLM 답변을 방해할 수 있다.
- 문자 수는 생성 모델의 실제 token 수와 다르다.
- LLM 답변 정확성, 근거 충실성, 지연 시간과 비용을 아직 측정하지 않았다.
- 생성 모델 선택 후 prompt template, token budget, 인용 형식과 근거 부족 시 답변 거부 규칙을 구현한다.

## CTX-002: 생성용 context 압축

15개 평가 질문에서 다음 조합을 grid search했다.

- retrieval top-k: 2, 3, 4, 5
- max chunks: 6, 8, 10, 12
- max chars: 6,000, 8,000, 10,000, 12,000
- neighbor window: 1 고정

정답 근거 포함률 100%를 유지하는 가장 작은 설정:

- retrieval top-k: 3
- max chunks: 6
- max chars: 6,000
- 평균 context: 4.87 chunks, 5,398.5자
- 최대 실제 context: 5,963자

| 지표 | CTX-001 | CTX-002 | 변화 |
|---|---:|---:|---:|
| 정답 근거 포함률 | 100% | 100% | 유지 |
| 평균 chunk | 9.4 | 4.87 | -48.2% |
| 평균 본문 문자 | 10,069.8 | 5,398.5 | -46.4% |

검색 결과를 2개로 줄이면 정답 근거 포함률이 80%로 하락해 채택하지 않았다.
